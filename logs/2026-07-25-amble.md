# Build Log: Amble
**Date:** 2026-07-25
**Status:** deployed

## Idea Source
IDEAS.md (first entry, now removed): the Tokaido-shaped unhurried travel game. Quoted essence:
"the traveller who is FURTHEST BEHIND takes the next turn… every stop you skip past is a turn you
hand your rivals… the tension is entirely 'how much do I give up to reach that one spot before someone
else takes it'". Mechanic taken, identity not: original name (Amble), original procedural woodblock
art, no reference to the source. Input decision (principle #23): touch, chosen on purpose — this is a
turn-based, zero-hidden-information board game whose whole verb is "choose a spot on the map"; a sensor
would be noise bolted on. The last sensor build (uproar) was two runs ago, so the fleet is not overdue.

## Game Details
- **Name / repo:** Amble / ben-gy/amble
- **Genre:** board
- **Core loop:** move forward to any open stop, take its reward, then the furthest-behind traveller
  moves next; spend a fixed budget of claims on the right stops across a one-way road.
- **Multiplayer:** live P2P 2–5 (lockstep) + solo-vs-bots + invite-link/typed-code/QR rooms
- **Stack / render:** vanilla-ts / canvas (winding vertical road) + DOM (menus/HUD/results)
- **Engine modules used:** net, rematch, turn, lobby (+ qr), rng, sound, storage, mobile

## Juice
Procedural SFX (select/coin/jump/powerup/blip/win/lose), tweened token slide + auto-scroll camera,
particle burst in the stop's colour on landing, inn shake, lantern-glow pulse on reachable stops,
3-2-1 count-in with audio. All shake/particles respect prefers-reduced-motion.

## The balance sim (built FIRST, overruled the design — principle #18, the idea's own flag a)
Recorded in BALANCE.md. With no cap on stops, "furthest-behind moves next" is so strong a catch-up
device that always taking the shortest hop wins 100% (an ambler took 41 landings to a leaper's 6).
Capping the SCORING alone didn't touch it — the dawdler still filled every capped bucket. The fix is a
CLAIM BUDGET (every traveller claims the same number of open stops; inns are free), which conserves
turns so the "which stops" decision is the whole game. A second bug hid inside: `clonePlayer` dropped
the `claims` field, so `NaN >= budget` never fired and the budget silently didn't exist. Fixed and
MUTATION-VERIFIED (reverting makes ambling dominate again; balance test goes red in all three modes).
Final (n=60/cell, replicated, 4p seat arm n=200): no pure style dominates; skill beats random 97–99%;
4p seats 22–30% at n=400; leader@30% of road 43–54% rising to 84–98% at 85%; blowouts bounded; all
terminate.

## Errors & Resolutions
- **Ambling wins 100%** (the idea's flag a): fixed with a per-mode claim budget; the real leak was
  `clonePlayer` dropping `claims`. Mutation-verified.
- **Inn meal menu opened on pointerup then closed on the following click** (backdrop under the tap) —
  invisible to unit tests, fatal on real touch. Fixed with a 350ms arm-guard on the backdrop close.
  Caught only by playing it in the browser.
- **Lobby rebuilt on every net event**, wiping the engine's qrOpen sticky state (QR yanked off screen
  mid-scan — the ballast/turntide "rebuilding-engine-view-drops-state" lesson). Fixed to repaint() in
  place.
- **Room-level rounds/move-channel torn down on round start** — `startNetRound` calls `teardown()`,
  which was running the enterRoom cleanups and destroying the rounds + `mv` channel the instant a round
  began (board froze; move-receipt didn't repaint). Moved those to leaveRoom only, and added a
  frame-loop self-heal (`view.game !== m.state → repaint`) so the board can never freeze on a missed
  repaint. Both caught by the live two-peer test.
- **Invite link landed on the cold menu** instead of joining. boot() now honours `?room=`.
- Note: the in-pane canvas getImageData returns all-zero (a known automation readback limitation), so
  the mandatory contrast pixel probe fell back to contrast.test.ts + visual confirmation (the winding
  road is canvas-only and renders vividly on every screenshot).
