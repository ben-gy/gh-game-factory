## Idea Source
IDEAS.md — the third queued geography idea (a Worldle/Globle-style mystery-country
proximity guesser). The two ahead of it were left in the queue with documented reasons:

- **GeoChess (#1):** the exact rules are genuinely unconfirmable. Research (WebFetch +
  WebSearch) found geochess.org now serves only a "Coming Soon" / gated SPA — the
  turn-by-turn mechanic could not be read, exactly as the idea anticipated. The idea's
  own instruction is explicit: *"DO NOT ship a guessed mechanic without confirming it
  first; a wrong rebuild is not a rebuild,"* and a verbatim-name rebuild needs the
  author's permission. In a non-interactive run I can confirm neither, so I did not
  build it and did NOT remove it from the queue.
- **Photo-drop guesser (#2):** hinges on curating ~150 verifiably-CC0/PD geotagged
  landmark photos — the geo-note calls this "the make-or-break." Autonomously
  guaranteeing every photo's licence provenance carries a real copyright risk
  (principle #3/#7 = hard fail) that I can't de-risk unattended. Left in the queue.

Beeline is pure facts + public-domain Natural Earth vectors — zero image-licensing
risk, deterministic, unit-testable, trivial P2P. The ideal clean autonomous build.
Both skipped ideas remain in IDEAS.md for a run where they can be confirmed/reviewed.

## Game Details
- **Name / repo:** Beeline / ben-gy/beeline
- **Genre:** puzzle (the fleet's first geography game)
- **Core loop:** find a hidden country using only distance + direction + warmth; solve in as few guesses as possible
- **Multiplayer:** live P2P versus 2–6, a parallel same-seed race (no game state on the wire)
- **Stack / render:** vanilla-ts / canvas map + DOM UI
- **Engine modules used:** net, rematch, turn, lobby, qr (via lobby), rng, sound, storage, mobile, identity

## Data pipeline
- `scripts/gen-geodata.mjs` fetches Natural Earth 1:110m Admin 0 Countries (public
  domain) once and emits `src/data/countries.json`: 175 countries with id, name,
  continent, centroid (LABEL point), simplified exterior polygons, and a mode pool
  (core / extra / territory). 113 KB uncompressed, **~38 KB gzip** — comparable to a
  word-game dictionary, fully offline. Facts aren't copyrightable; NE vectors are PD.

## Juice
- Procedural SFX: pitched per-guess tone rising with proximity, win/lose, 3-2-1-GO
  count-in (beat/go). Haptics (navigator.vibrate) per guess. Screen has a beeline arc
  drawn from the last guess to the answer on reveal, a pulsing green ring on the
  mystery, a particle burst, and a row-in animation on each guess. `prefers-reduced-
  motion` degrades to no shake / instant fills.

## Errors & Resolutions
- **Arrow double-encoding (real bug, found in-browser):** the direction arrow picked an
  octant glyph by bearing AND rotated it by the same bearing, so it pointed the wrong
  way (Western Sahara's arrow pointed north when the answer, Senegal, is south). No unit
  test saw it because none rendered the row. Fixed to a single encoding (fixed ↑ rotated
  by the bearing); added `tests/ui.test.ts` pinning it; mutation-verified (reverting
  turns it red); re-verified live (South Africa→Egypt N, Norway→Egypt SSE, India→Egypt WNW).
- **Cabo Verde alias pointed at a missing target** (not in NE 110m) — removed the alias.
- **Contrast tuning:** darkened the land plate and lightened the `hot`/`cold` buckets so
  every warmth bucket clears ≥3:1 against BOTH sea and land (pre-checked numerically
  before writing the palette, then pinned by contrast.test.ts + the real-pixel probe).
- **Browser-pane clicks:** the in-app pane occasionally dropped the first `computer`
  click after a screen transition; used DOM `.click()` / element refs for reliable
  driving. Not a game bug.
