**Input question (principle #23):** what if the input were not a finger on glass? Considered a
gyroscope tilt for the die, but rejected it — the last two builds (waft/camera, teeter/gyro)
were sensor runs, so a sensor is not overdue; and a die that steps in four discrete directions
wants deliberate directional input, not a shake. Chose **touch on purpose** (swipe / tap-to-step
/ arrow keys).

## Game Details
- **Name / repo:** Facet / ben-gy/facet
- **Genre:** puzzle
- **Core loop:** roll a die so the number face-up matches each rune when you land on it; collect
  all, then reach the vault in the fewest rolls (scored vs an exact BFS par).
- **Multiplayer:** live P2P, parallel same-seed race, 2–6, fewest rolls wins (no board state on
  the wire).
- **Stack / render:** vanilla-ts / canvas
- **Engine modules used:** net, rematch, turn, lobby, qr, rng, sound, storage, mobile, identity

## Design highlights
- **The board is a pure function of (mode, seed)** and solvable BY CONSTRUCTION: a random
  die-walk lays runes (required face = the top face at first arrival) + the vault at the walk's
  end; holes are placed off the optimal solution's cells (solve hole-free, place pits off it,
  re-solve); rejection-sampled so par lands in each mode's band.
- **Exact BFS solver** over (cell × 24 orientations × collected-mask) — ≤ ~14k states — gives par
  and one optimal line. This is the referee for the balance sim and the honest score.
- Three modes with real spread (the RULE is the axis): Trail (any order), Chasm (pits reset the
  die), Vault (ordered runes).

## Juice
Tumbling die (slide + tip, pip face crossfades old→new), collect burst + small shake, magenta
win burst, coral fall shake; procedural SFX per action (roll blip, collect coin, mismatch/fall/
win); haptics; timer bar. Respects prefers-reduced-motion.

## Errors & Resolutions
- Chasm first generation left <5 free cells for pits (the walk covered too much of the 6×6):
  fixed by placing holes off the SOLUTION path (solve hole-free first) instead of off the whole
  walk — cleaner and leaves ample room.
- Latent ordered-collect bug: `canCollect` assumed array index == order field; generation
  guarantees that, but a hand-built test exposed it. Reworked to check the `order` field
  directly (correct for any indexing).
- Test-hook honesty: `__facet.state()` returned `soloState ?? race?.state`, so a stale solo game
  masked the live race in the 2-tab smoke (read par 26 instead of the race's 17). Fixed to prefer
  `race?.state` and clear soloState on room entry (game code was always correct — the hook was
  misleading verification only).

## Note
Two tabs of one browser share localStorage, so both peers showed the handle "Player 890" in the
smoke test. Real separate devices get distinct random handles (per-device, per-origin storage) —
this is the two-tabs-same-browser degenerate case, not a shared-literal-name bug.
