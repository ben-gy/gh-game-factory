# Build Log: Huntress
**Date:** 2026-08-11
**Status:** deployed

## Idea Source

IDEAS.md, top of the board-game initiative:

> **Huntress** (Amazons / Game of the Amazons-shaped) — each turn a queen slides any distance then
> fires an arrow that permanently blocks a square; the board keeps shrinking until a player can't
> move and loses. vs 2, lockstep + bot; board size = modes.

Removed from the queue this run. Mechanic only — original name, procedural art, original copy; the
source game is named nowhere in the product.

## This run was a rescue, not a greenfield build

The **2026-08-10** run built the game and was cut off before it wrote a README or a plan, before
`git init`, before any deploy, and before a single browser check. It left behind a substantial,
well-structured implementation with **218 passing tests and a clean `tsc`**.

That state is exactly the trap this factory keeps re-learning: a green suite is not a working game.
So the run went: reconstruct the missing docs → **audit the inherited code adversarially** → fix →
verify in a real browser → deploy.

## Game Details
- **Name / repo:** Huntress / ben-gy/huntress
- **Genre:** board (2-player perfect-information abstract)
- **Core loop:** slide a huntress along a clear queen line, then fire an arrow from where she landed;
  that square burns forever. The square she *left* is empty behind her, so sealing the doorway you
  just came through is the game's central manoeuvre. No captures. You lose when you have no legal
  ply; once the sides are sealed apart it adjudicates on ground held.
- **Multiplayer:** live P2P, **lockstep**, 2 players + spectators.
- **Stack / render:** vanilla-ts / DOM board (buttons) + a particle canvas overlay.
- **Engine modules:** net, rematch, turn, lobby, rng, sound, storage, mobile, identity, qr (via lobby).

**Termination is structural, not hoped for:** every ply burns exactly one square and nothing
un-burns, so the ply cap is arithmetic. **Every message carries the entire ply log** (~56 small
ints) rather than a delta, which makes a dropped datagram unobservable, lets a quiet peer self-heal
within one 2s heartbeat, and puts a spectator arriving at move 30 instantly in sync. An illegal ply
off the wire is reported as a **build mismatch**, not absorbed.

**The bot is the product for one player.** Negamax + alpha-beta + iterative deepening over a
two-stage candidate list (an 8×8 opening has ~1,600 plies, so destinations are scored first, then
that huntress's arrows), evaluated by a two-metric queen-distance/king-distance territory flood plus
mobility that tapers as the board burns down.

## The audit

A 36-agent adversarial pass over the inherited code: six independent lenses (P2P contract, mobile
and layout, rules and bot, required surfaces, juice and contrast, shippability), every candidate
finding then handed to an independent agent whose job was to **refute** it. 30 candidates, 9 refuted,
the rest confirmed and fixed.

Multiple lenses converged on the same defects independently, which is the signal that mattered.

### Ship-blockers

1. **A third peer was seated onto side 0.** `maxPlayers: 2` on the engine lobby is only a caption;
   `createRounds` freezes whatever roster voted, and `sideForRound` — `(i + round + 1) % 2` — aliases
   roster index 2 onto the same side as index 0. Two peers both believe they are Rust, both submit a
   ply for it, both latch `fault = 'desync'`, and the round dies for all three. Sharing an invite
   link into a group chat is the ordinary way a room fills, so this was the expected case.
   Fixed by a `seatFor()` that slices the roster to `SEATS` and hands everyone else the (already
   working) spectator path.
2. **The arrow landing and every rejected tap were silent.** The game played cue `'thud'`, which was
   never a patch: `createSfx(boolean)` merges no custom patches, and `sfx.play()` on an unknown cue
   is a deliberate silent no-op in the engine. It cannot throw, cannot log, is inaudible to jsdom and
   invisible in a screenshot — so the game's signature moment made no sound at all, and under
   `prefers-reduced-motion` (which suppresses the flight, the burst and the shake) an arrow shot was
   a square quietly changing colour with **no feedback of any kind**.

### Serious

3. **A fault froze the round forever.** Every desync/build-mismatch path set the flag, repainted and
   returned — never touching `winner`/`reason`, so `isOver()` stayed false, `onEnd` never fired, and
   both peers sat on a dead board. The results screen already had copy for a faulted round that
   nothing could reach. Faults now end the round as `nocontest` (no winner: the two boards disagree,
   so neither reading is authoritative) and reach the summary.
4. **"Paused" paused nothing.** The bot kept thinking and, in multiplayer, the turn clock kept
   draining and auto-played the move the player had walked away from. It also offered no Restart
   (a required surface) and satisfied one of the four dismissal routes — Escape was bound to *undo a
   half-made ply* behind the card. Now: solo pause genuinely stops the clock and the bot; multiplayer
   pause is honest that the shared clock keeps running (pausing it locally would be a grief button);
   Restart added; all four dismissal routes.
5. **The multiplayer last-move trail marked your own previous move.** `last` was assigned on the
   local submit path only, so a P2P player could never see what their opponent had just done, and the
   arrow flight animated from the wrong square. Now derived from the shared event stream, which both
   the local and remote paths emit through.
6. **The pie/swap rule was unreachable, and had no UI at all.** `swapOpen` was cleared by the normal
   ply path on ply 0 — before the only window the gate could fire in — and nothing anywhere offered
   the choice. Removed rather than half-finished: measured first-move advantage is **45–53%** across
   the three modes, and sides already alternate every round, which is the mechanism that actually
   keeps a match fair.
7. **The top difficulty tier was not deeper than the middle one.** Measured, not argued: Warden
   (depth 4, 1100ms, kq 14 / ka 5) burned its **entire** budget and returned a **depth-3** answer —
   the same depth Ranger reaches in ~70ms. 13× the cost, a frozen main thread, no extra strength.
   Swept the candidate width and narrowed to kq 8 / ka 3, which completes a **true depth 4 in
   ~520ms**, i.e. deeper *and* half the freeze.
8. **The "picked up" ring was invisible.** Gold `#E9B44C` on the pale board: **1.45:1** on glade,
   **1.24:1** on shade — the single most important feedback in a three-tap turn. The contrast gate
   could not see it because `gold` was never in `ON_BOARD`. Replaced with a dark amber `#6B4A05`
   (5.93:1 / 4.82:1, 39 ΔE from its nearest neighbour) and **registered as a board mark**, so it is
   pinned from now on.
9. **The multiplayer turn clock rendered at the bottom of the page.** `.clockbar` had no `grid-area`
   in either the desktop or the landscape grid, so it auto-placed into an implicit row, detached from
   the HUD. Invisible to jsdom (no layout engine) and to a solo playthrough (no clock).

Plus: mode/difficulty chips were 40px against a 44px floor; `.trapped`/`.vacated` were toggled every
paint with no CSS at all, so the "sealed in" flourish and the doorway marker never rendered; and the
match tally counted by **seat** while the player swaps seats every round, so it reported which
*colour* had won more rather than your record.

### What a real two-tab run found that no unit test could

**`onPeers` fires when a peer LEAVES, too** — and the screen wired it straight to `peerBack()`, which
cleared `missing` and reset `silence` to zero. So the departure armed the hold and the very same
departure immediately disarmed it, closing **both** routes to a walkover. The survivor sat on a live
board waiting for someone who was gone, indefinitely. Only a genuine two-peer session surfaces this.

A methodological note worth keeping: **closing a tab in the automation pane does not stop the page.**
The first attempt at the host-leave test looked like a hang, but the "closed" peer was still alive
and heartbeating. A genuine unload (navigating the tab away) is what actually exercises the gate.

**Every fix is mutation-verified**: the fix was reverted, the new test confirmed RED, then restored.
One of those reverts caught a *decorative* test — the first cut of the cue-table test built its own
mixer and stayed green while `main.ts` called `createSfx(boolean)`, i.e. while every custom cue in
the shipped game was silent. It now asserts against `main.ts`'s own call.

## Juice
Arrow flight tween from huntress to landing square, burn bloom + ember particles, screen shake scaled
to the event (a nudge on a burn, a jolt on a seal), last-move trail, legal-target dots that differ by
stage (green discs to run, plum rings to shoot), the doorway marker on the vacated square, a pulsing
alarm ring on a sealed-in huntress, procedural cues for lift/arrow/seal/win/loss plus the 3-2-1-GO
countdown, and haptics. All of it degrades under `prefers-reduced-motion`.

### The custom domain could not be created — read this before assuming it was missed

`huntress.benrichardson.dev` **does not exist**. The Cloudflare zone `benrichardson.dev` is at
**exactly 200 DNS records**, the plan's ceiling, and the API refused with `81045 Record quota
exceeded`. No `huntress` record was present to reuse.

Freeing a slot means **deleting some other live property's DNS record**, which would take that
property offline — not a call to make unattended. So the game ships on GitHub Pages' own host at a
sub-path instead:

**https://ben-gy.github.io/huntress/**

This is not cosmetic. Shipping the `public/CNAME` file anyway would have made Pages **301 the working
URL to a hostname that does not resolve**, taking the game completely offline — so the CNAME file is
deliberately absent, `vite`'s `base` is `/huntress/`, and the manifest's `start_url`, `scope` and
icon paths carry the sub-path or every asset 404s. `tests/manifest.test.ts` pins all of it together,
so if the subdomain is ever created they move as one.

**Action for the user:** either prune stale records from the zone or raise the plan's record limit,
then create the `huntress` CNAME → `ben-gy.github.io`, restore `public/CNAME`, set `base: '/'`,
revert the manifest paths and the absolute URLs, and set the Pages cname.
