# Build Log: Salient
**Date:** 2026-08-20
**Status:** deployed

## Idea Source
IDEAS.md, first entry in the big-game queue:

> **Bloomfront** (RTS, small) — a dozen units, three build options, one map, real unit interaction
> (counters, positioning, control groups by drag). Lockstep on a fixed timestep so no state crosses
> the wire, only commands. Depth from how units interact, never from unit count. vs 2 + bot.

Renamed to **Salient** — "bloom" is already the identity of a shipped game (hexbloom), and a salient
(a bulge pushed into somebody else's line) is what the game is actually about. Removed from IDEAS.md.

## Game Details
- **Name / repo:** Salient / ben-gy/salient
- **Genre:** strategy (the directory's fixed category for RTS)
- **Core loop:** hold seams for ore, spend it on three unit types, and fight over a front line where
  every death leaves a wreck that is simultaneously half the unit's cost and a wall neither side can
  shoot through. Nothing heals; armour spalls permanently.
- **Multiplayer:** live P2P, 2 players, **deterministic lockstep and hostless**. One channel (`ord`).
- **Stack / render:** vanilla-ts / canvas
- **Engine modules used:** net, rematch, turn, lobby, identity, rng, sound, storage, mobile (v1.4.0)

## How the design was reached
A ten-agent workflow: three independent systems designs from distinct angles, a three-lens judge
panel (systems / mobile-UX / implementation), a synthesis, and three adversarial refuters. DROSS won
on aggregate (91.5 to SALTMARCH's 85). The judges' cuts were applied and the synthesis's additions
were mostly rejected as scope:

- **Cut the six-option upgrade tree** (two judges: "content, not systems"; 27 loadouts per side).
- **Narrowed line-of-fire blocking to Anvils and wrecks.** In the original every body blocked, and
  with 24 units on 192 tiles a 4.5-tile line is almost always occupied — the Arbalest would be
  silent for reasons no player could see. "Big things block, small things do not" keeps every
  situation the rule exists for and makes the cause legible.
- **Cut melt/scuttle** (two judges: dead content in the default mode).
- **Rejected the synthesis's own additions** — elevation, nerve regeneration, ash rings, a graze
  rule, per-seam build slots — as a bigger game than one pass, not a better one.
- **Accepted from the refuters:** the direction-canonical line of fire, no rust on a Forge (a
  symmetric clock kills both Forges on the same tick and leaves the winner undefined), tile-
  resolution hit-testing instead of a 44px disc, tap-selects-one with press-to-widen, and
  "any board tap is a move".

## Juice
Tracers on every shot, screen shake on a death, haptic tick on losing a unit, procedural audio
pitched by unit type and by the size of the body that died, capture arcs filling on seams, a rust
vignette that thickens at each doubling, and a split tonnage bar that answers "who is winning"
continuously. Combat cues are rate-limited to 55ms or a big fight is a buzz.

## The seven symmetry bugs the mirror test found
The first headless run read **0–8 in every mode**. Because the map is 180°-symmetric and the sim
makes zero random draws, two identical bots must stay *exact point reflections* for a whole match —
so any divergence is a bug and the first tick names it. A win-rate band (±7pp on n≈200) would have
seen "something is wrong" and located nothing.

1. `spawnTile` broke ties on the raw tile index → seat 0's reinforcements appeared one tile FORWARD
   of its Forge and seat 1's one tile BACK from its own.
2. A\* broke ties on the raw tile index → the two seats walked around the same obstacle in opposite
   senses, one systematically on the better side.
3. The bot staggered per-unit thinking by **entity id** → seat 0 planned on tick 0, seat 1 on tick 2,
   for the whole match.
4. **Damage applied inside the unit loop** → the lower entity id won every mutual kill.
5. **Movement applied inside the unit loop** → later units planned against a world in which earlier
   ones had already moved. (Held the mirror to tick 93 before this.)
6. **Separation pushed in place** → mirrored pairs resolved in different relative orders. (Tick 805.)
7. **`SUB` was 256.** `floor(x/SUB)` is only symmetric under the board's reflection when the width is
   ≡ −1 (mod SUB), so a unit standing exactly on a tile boundary was read one tile north on one side
   and not on the other — and captured a seam a tick early. **The scale is 255 for that reason.**

Damage and movement are now two-phase and separation accumulates before committing. The mirror holds
exactly, for a full match, in all three modes.

## Balance (measured, every seed run twice with the bot personalities swapped between seats)
Personality had to be de-confounded from seat: the sim is exactly symmetric, so an un-swapped sweep
measures "is personality A better than B". Before the swap, standing read a −140 ore seat lean that
was entirely an artifact.

| Metric | Result |
|---|---|
| Seat fairness | **exact** (mirror invariant), win split 15/17, 12/14, 17/15 |
| Median round | standing ~3:00, lastbatch ~1:47, theline ~2:09; nothing ever passes the hard clock |
| Salvage share of all ore spent | 33% / 67% / 26% |
| Cover fires per match (wreck + Anvil blocks) | 257 / 192 / 289 |
| Mis-targeted shots · silent guns · illegal shots · ledger breaks | **0 / 0 / 0 / 0** |
| Ablation: no salvage | **+332 ore** to the intact side — decisively load-bearing |
| Ablation: no orders at all | **+876 ore** — the game responds to being played |
| Ablation: no artillery discipline | **+120 ± noise** — see below |
| Skill gap: hard vs raw | **+333 ore**, ahead in 9/10 |
| Per-tick cost (sim + both bots, 14 units) | **0.06 ms** against a 50 ms budget |

**Recorded honestly rather than tuned until it looked good:** artillery "discipline" measured
**−360** on its first implementation — the ablated control *beat* the disciplined bot — because it
held a 70-hit-point Arbalest perfectly still while a Harrier walked up to it. Holding only at range,
and retreating when crowded, moved it to about +120, which is real but inside two standard errors.
It stays because it is cheap and not harmful; it is not claimed as more.

**Also fixed by measurement:** lastbatch matches ended in a **median of 56 seconds** because the bot
burned all six of its lifetime presses in the first three seconds and twelve bodies met at once. The
bot now rations presses against the clock.

## Errors & Resolutions
- **The survivor of a walkover was stranded on a frozen board.** The match genuinely ended — the
  fault was set, the roster showed the opponent absent — and the summary never appeared, because the
  one callback that navigates did not land. `takeover.test.ts` had asserted the fault and the
  `over` flag and *not* that the screen was told: "the match ended" and "the player was told" are two
  different claims. The screen now checks `b.over` on its own clock and the handoff is idempotent, so
  a frozen board is unreachable; three new tests cover walkover, Forge-kill and the clock.
- **Ore leaked** whenever two units died on the same tile: the wreck value was capped at 60 but the
  full amount was still counted as created. The zero-tolerance conservation audit caught it on the
  first run (3,560 broken ticks per match).
- **Inter-peer clock skew** measured 639 vs 479 ticks between a foregrounded and a backgrounded tab,
  which makes a late order force a deep, visible re-derive. A peer now holds station if it is more
  than two seconds ahead of what the other has reported — a cap, not a barrier, so nothing deadlocks.
- **The mechanism audit was initially measuring itself.** Its first two "violations" were artifacts:
  it compared post-tick positions against a pre-tick decision, and its re-derived priority score
  truncated a term the game truncates once at the end. Both fixed; the audit now snapshots the world
  the shooter actually saw, and only issues a verdict where the answer cannot depend on the choice of
  rasteriser (an empty corridor, or a body squarely on the line).
- **The cover metric read zero** because it sampled only the final tick, by which time one army is
  dead and nobody is in range of anybody. Sampling throughout showed 192–289 blocks per match.
- **A vacuous tutorial assertion.** The first "step 4 is a real blocked shot" test passed with the
  Anvil moved off the line, because Chebyshev triangle-equality does not prove collinearity *and*
  the lane I had chosen was blocked by a ridge, so the Anvil was irrelevant. It now asserts strict
  collinearity and a **positive control** (move the Anvil aside and the shot must land).
